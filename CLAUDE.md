# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this package is

`AUCMR/` is the implementation of the AUCMR system (TOSEM 2026 submission, see `../samples/main.tex`). It is a **two-layer architecture**:

1. **Retrieval Layer** — multimodal RAG: cross-modal late-interaction + CMAB-TopN (LinUCB) + page-level retrieval over Milvus.
2. **Elaboration Layer** — **CREST** (Cockburn-Reflective Elaboration with Source Tracing): a multi-agent system that, given a use case name + a long multimodal PDF, produces a Cockburn 8-slot fully-dressed use case where every claim is traceable to source pages.

The v1 four-stage pipeline (actor identification → use case identification → actor-uc validation → detail use case generation) was **removed**. The current entry point invokes only CREST.

## Commands

Run from the repository root so `from config...`, `from utils...`, `from crest...` resolve.

- Run the full CREST elaboration:
  ```bash
  python main.py \
      --project <milvus_collection> \
      --actor "Pilot" \
      --use-case "Authenticate via Link16 Terminal" \
      [--file-names doc1 doc2 ...] \
      [--output <root_dir>] \
      [--max-slot-rounds 5]
  ```
  Default behavior: searches every PDF in the Milvus collection. `--file-names` restricts the search.

  Output is always written to disk as **two JSON files** under `<root>/<project>/`:
  - `<actor>_<use_case>.json` — main output (slots, claims, quality flags, revision history)
  - `<actor>_<use_case>-evidence.json` — full evidence card content keyed by `card_id`, plus `referenced_card_ids`

  `<root>` defaults to `./results` and can be overridden with `--output ROOT`. The actor/use-case stem is sanitized: spaces → `_`, other filesystem-unsafe chars stripped (unicode letters incl. CJK preserved).

- Syntax-check all Python files:
  ```bash
  python -m compileall .
  ```

- Run preprocessing for a PDF already converted to page images:
  ```bash
  python -c "from pipelines.preprocess_minio_multi_img import init_model, preprocess_multiImg; m=init_model(); print(preprocess_multiImg('OR2UC', '/path/to/page_images', 'jtvauctions', m))"
  ```

- Check a Milvus bulk-import job:
  ```bash
  python -m pipelines.check_progress JOB_ID --project COLLECTION_NAME --watch
  ```

- Tests: a single `tests/__init__.py` file exists. Currently it does not pass — the test suite is being rewritten as part of the CREST refactor (see `../.claude/plans/aucmr-crest-immutable-journal.md`).

## Runtime dependencies and environment

There is no declared dependency file. Imports show the code expects at least: `torch`, `transformers`, `stable_baselines3` (legacy — PPO replaced by LinUCB), `openai`, `pymilvus`, `minio`, `json_repair`, `numpy`, `tqdm`, `Pillow`, `PyMuPDF` (`fitz`).

External services are required at runtime:
- Qwen/DashScope-compatible OpenAI client created in `config/settings.py`, used through `services/model_service.py` (text mode `qwen-max` / vision mode `qwen-vl-max`).
- Milvus at `MILVUS_URI` stores the page-image embedding collections.
- MinIO is used by Milvus bulk import for parquet files generated by `RemoteBulkWriter`.

## Architecture overview

Top-down, the repository layers:

- `main.py` is the CLI entry point. It (1) lazy-loads the retrieval stack via `services.model_registry.registry`, (2) builds a `retrieval_fn` adapter and a `ModelProvider`, (3) constructs `CRESTOrchestrator`, (4) calls `.elaborate(actor, use_case_name)`, (5) serializes the resulting `UseCase` to JSON.

- `crest/` is the elaboration layer. Read-order to understand it:
  - `crest/schemas.py` — dataclasses (`UseCase`, `SlotContent`, `Claim`, `EvidenceCard`, `QualityFlag`, `RevisionRecord`) and the `CockburnSlot` enum / `COCKBURN_DEPENDENCY_ORDER` list.
  - `crest/orchestrator.py` — `CRESTOrchestrator.elaborate()` iterates `COCKBURN_DEPENDENCY_ORDER` (Goal → Primary Actor → Preconditions → Trigger → Main Flow → Alternative Flow → Exception Flow → Postconditions), running `per_slot_dcrrm_loop` for each slot, then runs `cross_slot_revision` (the DRA Pass). Primary Actor is short-circuited from the `--actor` argument. After the Goal slot it runs a fail-fast check (`_goal_is_resolvable`); if the use case name cannot be resolved against the document, downstream slots are skipped and an `unresolvable_use_case` flag is emitted.
  - `crest/agents.py` — three agent functions (`query_designer`, `evidence_collector`, `answer_generator`), the per-slot DCRRM loop (`per_slot_dcrrm_loop`), `check_convergence`, and the cross-slot DRA Pass (`cross_slot_revision` + `_detect_consistency_grouped` + `claim_patcher` + `_apply_patch`).
    - `query_designer` (LLM): generates 2-4 search queries or `[]` to terminate; performs retrieval directly so its results can be reused by `evidence_collector`. Built-in early termination via query-text overlap and page-set overlap thresholds (parameterized at the orchestrator level).
    - `evidence_collector` (LVLM): groups retrieved pages by consecutive page numbers, reads each region, asks the LVLM to assess `is_complete`, and on incomplete regions chains adjacent pages (`next` / `previous` only — non-adjacent `cross_ref` resolution is intentionally not supported) up to `max_page_chain` until completeness is reached or the chain bottoms out (in which case the claim is emitted with a `region_incomplete` marker).
    - `answer_generator` (LLM): writes slot content from the available `EvidenceCard`s. Every claim must reference at least one card by `card_id`. Unknown references trigger a single retry with the valid-IDs list; remaining unknown references cause the affected claims to be dropped and an `evidence_invalid` flag to be raised.
    - `cross_slot_revision` (DRA Pass): three-step linear flow — **Detect** (2 grouped LLM calls: vertical [preconditions/trigger/main_flow/postconditions] + lateral [main_flow vs goal/actor/alt/exception]) → **Repair** (per-issue `claim_patcher` returning modify/remove/add/need_evidence; ordered slots auto-renumber on insert/remove; need_evidence escalates a single retrieval round, deduping any colliding card_ids) → **Annotate** (re-run detect once; remaining issues become `unresolved_inconsistency` quality flags). No multi-round iteration.
  - `crest/prompts/__init__.py` — `string.Template` prompts for every agent: `QUERY_DESIGNER`, `EVIDENCE_COLLECTOR_SINGLE_PAGE`, `EVIDENCE_COLLECTOR_REGION`, `ANSWER_GENERATOR`, `CONVERGENCE_CHECK`, `CONSISTENCY_DETECT_VERTICAL`, `CONSISTENCY_DETECT_LATERAL`, `CLAIM_PATCH`. The 7 cross-slot rules are inlined directly into the two DETECT prompts (no separate rule-list constant).

- `services/model_registry.py` — singleton `registry` that lazy-loads Milvus retriever, Jina embedder, LinUCB policy, PCA assets, and the Qwen client. Exposes `get_retrieval_adapter()` (closure that calls `utils.retrieval.retrieval_service`) and `get_model_provider()` (wraps `services.model_service.qwen` calls into a `crest.ModelProvider`). The LinUCB instance is **shared across slots** — its state accumulates over the full elaboration run.

- `services/model_service.py` wraps Qwen chat completions: text mode (`qwen-max`) when no images, vision mode (`qwen-vl-max`) when images are passed; base64-encodes images and supports corrective follow-ups on retry.

- `utils/retrieval.py` (`retrieval_service`) connects a query string to page-image retrieval: embed → LinUCB selects coarse top-N → `MilvusColbertRetriever.multi_img_search()` returns page-image paths.

- `config/milvus.py` defines `MilvusColbertRetriever` (collection creation, multi-vector search/reranking, hybrid text search, bulk insert prep, import progress).

- `pipelines/preprocess_minio_multi_img.py` prepares a Milvus image collection from page image files. `pipelines/upload_milvus.py` and `pipelines/check_progress.py` support that flow. (Note: `pipelines/upload_milvus.py` currently has an unimplemented `pass` stub that needs to be filled in before being used.)

- `utils/pdf_image.py` converts PDFs to numbered page PNGs. `utils/image_merge.py` merges page images for the LVLM-direct experiment baseline.

- `experiments/` contains alternate baselines that bypass parts of the CREST loop or use merged images with an LVLM directly. They are useful as comparison baselines but contain hard-coded paths.

## Important implementation notes

- Configuration is centralized in `config/settings.py` and is currently hard-coded (API/service settings, local model paths, collection names). Prefer changing that file rather than scattering new constants across scripts.

- `utils.feature.build_state_for_query()` accepts a plain query string and embeds it via the cached embedder; `utils.retrieval.retrieval_service()` calls it with no Milvus client argument. Older docs that say it expects a query dictionary + `milvus_client` are out of date.

- Milvus filters are built from Python lists in several places. Keep `file_names` as a list of plain strings (e.g. `['jtvauctions']`) unless you also update the filter construction.

- Many scripts write outputs under `results/`; `main.py` creates the directory automatically when `--output` is supplied.

- CREST is invariant-driven: every claim must trace to evidence cards. If you add new agents or modify `answer_generator`, preserve the unknown-evidence-ref retry-then-flag behavior; silently dropping invalid references reintroduces the bug that `_collect_invalid_refs` was added to prevent.
