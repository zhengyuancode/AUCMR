# L3 来源内容正确性与关键行为保留

协议 AUCMR_L3_2.0.0，设计日期 2026-10-21。

本设计采纳第二轮意见：内容审计覆盖正式比较的全部最终输出；有限场景检查覆盖正式主实验目标，每目标一个核心成功场景，来源明确时增加一个影响结果的条件或分支场景。两个用例只做流程小试。撤下旧 RCR，不建立全文需求全集。

## 当前交付状态

- 交付设计、机器可读配置、记录规范、完整角色提示、固定样例、验收条件、实现任务书、论文方法与表格模板。
- 当前没有实现正式评价执行器，没有发送评价模型请求，没有生成真实场景答案或研究分数。
- input_inventory.json 是本轮读取的候选输入快照，不是语义审定，不等于旧稿结果来源已经锁定。
- 原 design_v1、现有 AUCMR 代码、原输出和论文均不改动。本设计明确替代 design_v1 中的 L3 全文参照流程及其 L4 依赖，不修改 L1/L2 的实际实现。

## 阅读顺序

1. PROTOCOL.md：语义、公式、场景选择和运行顺序的权威定义。
2. config.json、cohort.json：固定规则与候选目标登记。
3. PROMPTS.md、CONTRACTS.md、records.schema.json：角色、材料权限及记录接口。
4. fixtures.json、ACCEPTANCE.md：模型校准和离线验收。
5. IMPLEMENTATION_TASK.md：交给代码 Agent 的完整任务。
6. PAPER_EXPORT.md、paper_methods_template.tex：数据到论文的字段对应与正文模板。
7. input_inventory.json、design_validation.json：已完成的机械检查与限制。

本轮使用 experimental-design 技能辅助确定事前冻结、评价单位和结果解释，并在 PROTOCOL.md 文末记录其来源。它不是本研究的评价有效性证据。

## 采纳与停止

可以因小试发现流程不可执行、判断不可靠或成本不可承担而停用或修订协议，保留原因和旧版本。不能因为正式结果不支持 AUCMR 就把有效结果删除、改口径或改场景。运行后只依固定技术条件决定是否具有报告资格，优劣结论由数据决定。

正式输出包含支持、混合、不支持和无法判断四种解释，不自动生成“显著优于”。
