# 从数据到论文

## 1. 自动填表的条件

export --paper 读取已验证判定，不调用模型写论文、不运行生成方法。只有通过一致版本和范围检查的数据能进入正式表。未完成项目仍导出状态与计数；不能生成一份外观完整但省略失败方法的表。

paper_values.json 必须带协议版本、run_id、输入manifest哈希、scope/scenario版本集合、正式/小试范围、来源文档数、主目标数、有效场景数、每方法任务数、模型绑定及语义/技术完成状态。所有指标在0至1之间保存，TeX显示百分数时统一乘100、保留1位小数。

## 2. 三张主表

### 表一：来源内容正确性

按文档×方法给行。固定列为：主目标数、有效非空/空输出/技术失败用例数、全部已读最终断言N、K/D/U/F、七方法共同非空目标数、共同集合CP_confirmed、未决下/上界。

原始计数覆盖该方法全部可解析目标，宏平均只针对明确列出的共同非空目标集合，脚注说明两者统计集合不同。不要把总K/总N冒充用例宏平均。scope不明的判断留U，不丢弃整个方法。共同集合为空时比例为--。

### 表二：选定场景行为保留

按文档×方法×场景类型CORE/BRANCH给行。列为：冻结场景数、RETAINED、PARTIAL、MISSING、DISTORTED、UNRESOLVED、技术未完成、未建立场景的目标数。另给目标×方法状态矩阵作为附录。

核心场景分母缺任何主目标时，表标题加“部分目标可评价”，报告全部未建立目标，不宣称正式范围已完成。分支未建立不是某方法失败，因此所有方法共享这个登记。可以显示RETAINED/冻结场景数；不使用RCR名称，也不称为全文需求覆盖率。

### 表三：错误类型与配对变化

错误表给每方法确认DELETE的来源冲突、关系错误、范围外、冗余计数，标明原因可重叠；另列NO_SUPPORT_FOUND等U原因。配对表给AUCMR与各比较对象在同一目标集的CP差值、未决差值界限，以及场景状态转移次数。无修订/通用修订/DRA配对还输出新引入错误和被修复错误的逐项记录，不把净断言数变化当真实编辑次数。

不自动加粗“最优”、星号或输出显著性。未决足以翻转差值时统一标记UNCERTAIN。CP和行为结论不一致时写MIXED，不合成一个方便排名的总分。

## 3. 核心字段映射

| CSV/JSON字段 | 论文含义 |
| --- | --- |
| n_final,k_keep,d_delete,u_unresolved,f_failed | 最终断言总数及四类判定 |
| cp_confirmed,cp_lower,cp_upper | 确认可保留比例和未决界限，非95%CI |
| common_cp_target_ids,common_cp_target_count | 七方法共同非空且无技术失败的目标集合 |
| state,core_status,branch_status | 制品与来源可评价性，不是方法分数 |
| scenario_kind,scenario_state | 核心/分支与保留状态 |
| source_locator_ids,matched_claim_ids | 原文与输出对应证据 |
| cp_delta,delta_lower,delta_upper | 相同集合上的配对差与未决界限 |
| paired_state_from,paired_state_to,count | 不同方法或修订条件的行为状态对应 |
| cost_cny,wall_seconds,api_requests,search_calls,page_reads | 评价开销，不能当生成方法开销 |

L3评价成本与生成方法成本分开报告。旧稿耗时不能与本次裁判费用直接相加后称某基线运行成本。

## 4. 预写结果句式

程序只选状态模板并填确定字段，不生成未经支持的解释。

- 完成且描述性改善：“在本次两份文档的已评价目标中，AUCMR的已确认可保留比例为……，比较配置为……。在预先选定的……个核心场景中，两者分别完整保留……和……个。结果限定于这些目标与场景，不代表全文需求完整性。”
- 混合：“AUCMR在……指标上较高，但在……出现更多缺失/错误；当前结果显示质量取舍，不能概括为全面改善。”
- 无改善：“本次评价未观察到AUCMR在……上的优势；……错误仍然存在。”
- 未决：“现有未决判定的可能取值足以改变比较方向，因此不作确定优劣判断。”
- 不完整：“已完成……/……目标，……因来源/技术问题未完成；以下仅报告已取得记录，不能代表完整正式实验。”

旧分数、旧CI、旧显著性和“全部五种配置均优于”不能由模板继承。分支场景多寡和裁判一致不作为独立项目样本量。
