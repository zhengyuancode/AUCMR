# L3 正式实验协议

版本 AUCMR_L3_2.0.0。本协议优先于 design_v1 的 L3 定义。配置控制数值，若配置与本协议冲突，停止相关任务并报告，不能择利执行。

## 1. 研究问题和边界

RQ-L3A：在同一来源和目标下，各方法生成的最终断言有多少被确认内容正确、范围相关且非冗余，错误表现在哪些条件和行为关系上？

RQ-L3B：在依据来源预先选定的有限场景中，各方法是否保留必要条件、关键动作、结果及它们的关系？

L3A 不受生成引用范围限制；L1 仍只检查断言自己的引用。L3B 检查与原文相符的行为保留；L2 检查用例内部一致性。它们可以相关，不作为相互独立的科学重复。L3B 仍使用小范围共同参照，不等于取消参照。

不再计算旧 RCR。不声称全文无遗漏、全局最小充分、可执行规范正确或实际下游收益。不通过保留重复内容、调整输出长度或挑选成功场景增加得分。

## 2. 实验集合与制品

### 2.1 主实验

cohort.json 登记原稿两份文档的全部 18 个候选，14 个历史主分析目标和 4 个历史诊断目标分别列出。历史标签只供协调器登记，不传给来源 Agent，不作为真值。

正式 L3A 主要比较原稿预先指定的 14 个目标与七种配置，即预期 98 份制品。L3B 要逐一处理这 14 个目标，不允许只保留两个小试目标。每目标最多两个场景，所以预计最多 28 个场景、196 个方法与场景配对；实际数量由来源核验决定，不能填造。

4 个历史诊断目标也保留全部输出与状态，可作内容审计和拒答诊断，结果单列，不混入主分析。有限搜索不能证明某行为在全文绝不存在，因此这里不宣称独立完成了全量可行性真值标注。

如果来源核验发现主分析目标的名称、参与者或成功场景不能成立，记录 SCOPE_UNRESOLVED 或 CORE_UNESTABLISHED，保留在目标台账中。不得悄悄换一个目标、缩小任务或根据系统接受结果重筛。L3A 可继续核验可判断内容，范围不明项为未决；L3B 的主实验完整状态为不完整。若需修改任务身份，先发布新 cohort 版本，再对所有方法统一处理。

### 2.2 输入版本

唯一代码入口 D:/Research/02_Code/AUCMR/AUCMR。输入制品按明确 output_root 和目标/参与者绑定，不能按文件时间挑最新结果，不能将 results 下的新 AUCMR 与 outputs 下旧基线无说明混用。

本轮静态盘点表明 outputs 下七种方法均有 18 个目标文件；results 和 results_baselines 是另一组候选输出，不能默认视为同一次七方法实验。input_inventory.json 只为方便实现记录这些事实。正式 prepare 必须重新登记选定文件的哈希、生成版本、能取得的模型/参数/调用记录，以及未知项。不能以当前配置补造历史调用版本。Stage1 全面历史追溯不作为本轮设计任务，但论文不得把未知来源说成已锁定。

只评价 slots 中七个生成槽位的最终 claims。排除外部给定的用例名称和主要参与者。保持文本、引用、顺序、步骤号，不拆分或重写复合断言。保留重复出现的各个 ID。pre_constraint_slots 不进入评价分母。

slot 缺失、类型错误、非空 raw_text 却没有 claims、正文与结构明显不一致，登记 STRUCTURE_ERROR，不自动当成空槽或自动切句。显式空槽为 VALID_EMPTY。ABSTAINED 仅由明确拒答记录确认。MISSING_FILE、PARSE_FAILED、STRUCTURE_ERROR 均与有效空输出不同。

唯一明确的早停适配例外：当前CREST输出若带有 quality_flags.flag_type=unresolvable_use_case，全部已存在的生成槽位均无非空claims且无非空raw_text，可规范为ABSTAINED并另记省略槽位。该标志只证明系统声明拒答，不证明目标确实不可完成，不能传给来源裁判。存在非空输出时不能用此标志清空内容。其他缺失claims的情况先保留结构异常，不能自行扩展例外。inventory的结构问题计数是待适配清单，不是最终语义错误数。

所有模型只看到中性制品和断言标识。屏蔽方法名、原文件路径、生成卡片前缀、质量标记、修复日志和旧分数。L3 的正文保留，来源引用标记不展示；源文件保持不变，私有映射可以还原。正文若直接泄露身份，登记暴露，不能偷偷改写。

### 2.3 补充文档与机制对照

仓库配置已有六份文档、36 个候选，不等于六份文档已经有完整七方法结果。新增文档作为 extension 组独立登记，沿用同一协议，先冻结目标、场景和方法集合，再评分；不与原两份文档混成一个主结果平均数。

当前14个主目标来自(20).zip的正文范围。如果后续正文正式扩大主实验目标集合，必须先更新cohort及冻结版本，并对新增主目标执行相同两部分评价；不能借本设计中的14这个历史数量漏评新主目标。

每个比较组登记input_profile。当前主组为FULL_SOURCE。共同文本任务的来源核验和场景选择仅使用各方法共同获得的文本材料，不能把只存在于隐藏图像中的行为当作该任务必要答案。针对模态贡献的同目标消融则可共用完整来源的场景，但须事先注明这是有意改变可见信息的机制实验，不能混作共同输入的公平性比较。

按需跨页与固定邻页对照、无修订/通用修订/DRA 对照使用同一 L3 评价。前者要求相同文档、目标、生成条件和可比读取预算；后者要求相同修订前制品、证据访问权限、修改权限和可比预算。配对初始制品哈希缺失时只能作最终系统比较，不声称净修复因果效果。

## 3. 有限场景的建立

### 3.1 目标范围卡

每个主目标先依据外部目标名称、参与者和来源建立 scope_card：目标含义、允许的角色/对象、任务起止边界、明确相邻但不属于目标的动作、别名、原文定位和未决。这是给 L3A 的范围边界，不是生成系统自己的 Scope Contract，不列出全部应有需求。

来源角色不读取方法输出、历史有效性标签、旧评分、AUCMR 自己的范围契约或任何生成证据卡。旧 Stage2 的 AI 草稿只可作为出处线索；保留 draft_origin，不将 AI_DRAFT、NOT_REVIEWED 转成专家真值。先核验源 PDF 哈希及页码映射。

### 3.2 每目标的选择规则

核心场景必须对应目标名称的一个成功实例。来源明确给出默认/基本路径时选择该路径；存在多个同等合法成功变体且未指定默认时，选择冻结 PDF 中首次有完整行为依据的变体。记录候选、出处、选择理由与未选理由，不以模型表现、篇幅、图片数量或生成器偏好排序。

第二场景从同一目标的核心动作或结果相关分支中选取。优先选择原文明示、会改变是否执行或执行结果的条件分支；存在多个同优先级候选时，按首次原文位置排序。没有找到可确认分支时记 NOT_ESTABLISHED_WITHIN_SEARCH，不能写成全文不存在分支。来源明确只有单一路径时可记 SOURCE_EXPLICIT_SINGLE_PATH。

每目标 core 最多 1 个，branch 最多 1 个。这里选择的是检查对象，不改变各生成方法原任务，也不给生成器额外场景提示。如果主流程选择另一合法成功变体，允许其在备选或其他位置表达选定场景；若未表达，计为本次选定场景未保留，不能推论整个用例无效。记录此种合法替代，不隐藏选择偏差。

### 3.3 场景检查点

每场景记录适用条件、必要角色和对象、关键动作、成功/终止结果及明确关系。每个 checkpoint 可以包含一段必要的条件—动作—结果关系，不把关系拆成孤立词语。至少有来源明确的动作和可观察结果；条件未规定就为 null，不用常识补齐。条件和关系记录只要求恢复这个场景，不要求重建七槽完整用例。

每个 checkpoint 必须有原页定位、原文摘录；图表或原型中不能直接摘录的内容保留原页区域和简短视觉说明，并由第二角色查看同一图像。数字、否定词、可选/必须、角色责任和跨页表头必须核对。原文外的标准或术语表不自动联网补齐。

不硬性规定 checkpoint 个数，以免拆分或截断语义。单场景超过 8 个 checkpoint 时作复杂度提示，检查是否能在不损失必要关系的情况下合并；无法合并时保留，不为了凑数删条目。记录复杂度和成本。

### 3.4 有限搜索和复核

SCENE_BUILD_A 用来源索引、标题、文内搜索及必要原页定位。每目标最多 12 次文内搜索、24 个独立原页；显式跨页引用可再读 8 页。达到上限不继续穷举，记录读过的页面及未决。页索引和目录可由离线程序全量提取，这不等于 Agent 完成全文语义审查。

SCENE_VERIFY_B 读取草稿涉及的全部原页及关系，独立判断依据和范围；可另用 6 次搜索、12 个原页澄清。先核查原文再给建议，不能只审核格式。A/B 分歧由 C 在同样原文范围中盲判后查看双方理由，最多一轮裁决。仍无法确定则不冻结该条，不用多数票替代证据。

scope_card、core、branch 及未决清单一起冻结。每个正式纳入的 checkpoint 均已通过第二角色核验；未决条目不进入任何方法的有效参照，数量与影响单列。核心场景无法建立时，目标不得从主队列消失。

正式参照一经评分启动不增加条目。发现来源错误时，立即标记受影响记录无效，修改版本并对该目标所有方法与机制变体统一重评，保留旧版。生成内容虽正确但未在场景检查点中，不自动判错，也不自动扩大场景。必要新增只进入以后预先冻结的研究版本。

## 4. L3A 内容审计

### 4.1 角色和证据

CONTENT_A 与 CONTENT_B 使用不同模型的新会话，看到同一份匿名完整输出、同一 scope_card 和冻结来源检索工具。看不到选定场景的检查清单，避免把有限场景误作整个目标范围；看不到 L1/L2/L4 判断、对方判断或修复理由。引用错误不直接影响 L3A，原文正确但无引用可以 KEEP。

每个评价批最多 6 条待判断言，同时提供完整用例上下文，保持原步骤和槽位。每批最多 12 次搜索、24 个原页读取；完整输出超请求上下文上限时，可按原槽位只读分页查看，必须遍历完整输出以核对冗余和指代，不能静默截断。上下文预算不足即技术未完成。

来源检索是共用离线全文搜索与页入口，不使用 AUCMR 的 LinUCB、卡片检索、质量标记或生成日志。模型可读取原页及相邻页，统一计费/配额规则。文字搜索失败不能直接认定视觉内容不存在。所有读页和查找请求入账。

### 4.2 判定

KEEP：来源支持全部实质性内容，属于目标范围，条件、角色、对象、动作和结果关系正确，且非不必要重复。

DELETE：存在可核验的错误或不合格原因。原因可多选：SOURCE_CONTRADICTION、RELATION_ERROR、OUT_OF_SCOPE、REDUNDANT。CONTRADICTION 与 RELATION_ERROR 必须有原文证据；REDUNDANT 必须关联等价断言。相同事实因不同槽位的必要职责再次出现不自动算冗余，不能仅因共用来源就删除。确属重复时按原槽位顺序及原索引保留第一个，后续记录为冗余，不按表述优美程度选择。

UNRESOLVED：在约定查找内未找到足够支持、来源含糊/冲突、目标范围不清或复合断言有部分不可核验。NO_SUPPORT_FOUND 是未决原因，不能写成确定捏造。若已发现足以否定整条断言的明确错误，即使另有部分未决，仍可 DELETE 并记录原因。

技术失败单列，不变成语义标签。复合断言必须整体成立才能 KEEP；允许多个来源共同支持但条件必须兼容。错槽诊断可记录，但不直接代替来源错误判定，槽位适配由 L1 独立报告。

### 4.3 统计

每用例、每方法有 N 条最终断言，K 为 KEEP，D 为 DELETE，U 为 UNRESOLVED，F 为技术未完成。必须满足 N=K+D+U+F。

N>0 且 F=0 时，主指标 CP_confirmed=K/N，中文名“已确认可保留比例”。不是沿用旧 CP 分数。U=0 时等于本协议完整 CP；U>0 时另报 [K/N,(K+U)/N] 未决界限。这不是统计置信区间。D/N 是确认应删除比例，不将 1-CP_confirmed 称为错误率。错误原因允许重叠，不能相加当成独立错误总数。

N=0 的有效空输出 CP 为 null、状态 EMPTY_OUTPUT；行为检查按第 5 节处理。F>0 或制品结构损坏时完整 CP 为 null，保存计数与完成度。不能删去失败断言后缩小 N。

每目标都报告 N、K、D、U、F、空槽数。K 只作为在统一原始断言协议下的计数，不解释成与表达粒度无关的“有效信息量”。

## 5. L3B 关键行为保留

BEHAVIOR_A/B 在新会话中读取一份匿名完整用例及同版场景、checkpoint 和来源证据，不读取 L3A/L1/L2 结果。允许多断言、多槽位共同表达。来源不要求的编号或模板位置不作为匹配条件；明确步骤引用必须存在且关系正确。

外部给定的用例名称和主要参与者只用于理解目标和省略主语，不单独计为生成器保留了行为。一个检查点至少应有生成断言实际表达对应动作或关系，不能仅靠输入字段判RETAINED。

每 checkpoint 判 RETAINED、PARTIAL、MISSING、DISTORTED、UNRESOLVED，并关联输出断言 ID：

- RETAINED：必要语义及关系均正确表达，可采用不同措辞或跨槽组合。
- PARTIAL：表达了部分必要内容，但少了某个必要条件、动作、结果或关系；没有明确错误关系。
- MISSING：没有表达该检查点的实质性行为。泛泛目标口号不算行为保留。
- DISTORTED：明确改变必要条件、否定、角色责任、对象、顺序或结果。同一适用条件下同时存在正确和错误表达，仍为 DISTORTED；另一合法分支不自动视为冲突。
- UNRESOLVED：材料或语义不足以可靠判断。技术错误另列。

场景状态由程序聚合，不由 Agent 直接打总分：任何必需 checkpoint 技术未完成则场景技术未完成；否则有 UNRESOLVED 则场景 UNRESOLVED；否则有 DISTORTED 则场景 DISTORTED；全部 RETAINED 为 RETAINED；全部 MISSING 为 MISSING；其他组合为 PARTIAL。已发现的错误单独保留，即使场景因未决不能作完整分类。

有效空输出对已建立的场景为 MISSING，不调用模型猜测。文件缺失、解析失败或输出结构错误为技术未完成，不能给 MISSING。没有冻结核心场景的目标为 CORE_UNESTABLISHED，不能记零分或满分。

主表分别报告 core 和 branch 的 RETAINED/PARTIAL/MISSING/DISTORTED/UNRESOLVED/技术未完成数量、可用场景数和完整性状态。主展示为完整保留个数/固定场景数，不合成旧 RCR，不用任意权重将 PARTIAL 折成半分。辅助文件可以给出比例，但必须命名“选定场景完整保留比例”，不能称全文需求覆盖率。

每目标最多两个场景，按 core/branch 分列可避免两个场景的目标获得双倍主表权重。正式核心场景表必须列出全部主目标，包括 CORE_UNESTABLISHED。分支表同时报告未建立/来源明确无其他路径的目标数，不能把未建立的分支藏在百分比之外。

## 6. 复核、抽检与稳定性

A/B 首判全部保存。C 对所有标签分歧、DELETE 原因实质分歧及随机一致项进行复核。C 先在不知道 A/B 标签和理由时判断，再读取匿名双方理由，一次裁决，保留首判和最终理由；复核不能超出对应角色的来源权限。无法解决为 UNRESOLVED，不以简单多数票强行定真。

C每个复核逻辑任务在收到材料以外最多补查6次文内搜索、12个原页；BEHAVIOR复核只可回看该冻结场景允许的原页，不扩大检查点。盲判与最终裁决共用这份预算，不能分别重置。

一致项按 project_id × decision_family 分层抽取 10%，向上取整且每非空层至少 1 项。family 为 CONTENT_CLAIM 或 BEHAVIOR_SCENARIO；行为以整个场景抽检，读取完整用例。实际抽样数与比例必须输出。来源场景的 B 全量核验另行计数，不能称为 10% 抽检。

稳定性按同样分层抽取 10%，A/B 各自在新会话复评，不读取旧判断；只报告波动，不择优替换首判或裁决。所有 Agent 会话不共享其他阶段历史。同模型新会话不代表统计独立。

随机种子固定 297154423。以 SHA256(seed|stream|stable_id) 排序生成呈现顺序和抽样名单，记录哈希算法、原顺序、样本 ID；不用 Python hash()，不以日期当种子。A/B 使用不同 stream，方法与目标交错呈现。抽样不依分数。provider 不支持模型随机种子时照实记 unsupported，不声称离线种子控制生成随机性。

## 7. 汇总与比较

保留 A_FIRST、B_FIRST、RECONCILED 三视图，论文主表默认 RECONCILED，附录报告 A/B 差异和稳定性。主评一致率是可靠性描述，不是准确率证明。

主表逐文档报告，不把同一文档的多个用例、断言或 Agent 当成独立项目。主分析只有两份文档，不自动输出跨项目显著性或对断言做独立样本检验。

CP 的严格七方法宏平均仅在相同目标集合上计算。每文档有效非空且无技术失败的七方法共同目标集合记 C_CP；报告全部目标的空输出/技术失败以及 C_CP 大小。只要 C_CP 少于该文档主目标数，表头写“共同非空输出子集”，不能用它代表所有任务。单方法可用集合均值只作诊断，不用于七方法排名。若 C_CP 为空，宏平均为 null。行为表仍保留空输出，不能沿用 C_CP 删除它。

确认比例的下、上界按相同 C_CP 取用例宏平均。AUCMR 对每个外部配置及 w/o 的差值也用该集合，报告点差、未决差值界限 [L_A-U_B,U_A-L_B] 和用例级胜/平/负。界限跨零时不输出确定优劣；界限不跨零也只说明对这些未决标签取值稳健，不等于统计显著或裁判无误。

行为比较报告核心与分支场景的成对状态转移及个数。不得只按 RETAINED 数选赢家而忽略错误增加或未决差异。主分析不生成 95% CI、p 值或星号；如以后需要推断统计，须先定义适用的独立文档集合和重采样单位并冻结新分析版本，不能看显著性再选择检验。

## 8. 小试与正式运行

先离线验收，再完成实际供应方绑定和固定模型样例，然后运行 JTV-01、S16-02 的七方法流程小试。小试检查的是能否定位来源、裁判能否识别已知错误、记录是否完整、未决是否可控、成本是否可承担。

固定样例具体阈值见 ACCEPTANCE.md，必须在任何真实方法得分可见前冻结。小试报告默认隐藏方法映射和排名。允许因技术缺陷修改一次提示/配置并保留版本和全部失败记录，不因某方法分数低修改。

小试结束后正式执行全部主目标的场景建立及全部输出评价。若协议、提示、模型、绑定参数和输入哈希均未改变，可导入小试中合格记录并标记 PILOT_CARRY_FORWARD；否则统一重评这两个目标，不混用旧协议分数。小试不是独立测试集，不能声称此前从未接触这些材料。

形式上执行完成不等于数据有论文报告资格。reportability.json 分别记录输入完整、来源场景完整、语义完成度、模型校准、权限/版本、预算和结果性质。部分结果仍可作为有限描述或失败记录报告，但不能自动填充完整主实验表。

## 9. 采纳规则

流程可靠性差可停用评价或修订后重做，保留失败。正式数据不支持 AUCMR 是科学结果，不是技术失败。不能看 AUCMR 排名选择是否保留协议、场景、用例、指标或结果。

运行后自动导出四类说明：SOURCE_OR_TECHNICALLY_INCOMPLETE、RESULT_UNCERTAIN、MIXED_OR_NO_ADVANTAGE、DESCRIPTIVE_ADVANTAGE_ON_OBSERVED_SET。最后一项也不得自动扩写为广泛或显著优势。技术上有效但不利的结果进入完整材料；论文可据此缩小或撤回优势主张。

## 10. 与其他评价同步

L1/L2 不从 L3 获得标签。L2 关于“L3 全面反映遗漏”的表述改为“结合选定场景行为检查，未检查的需求仍可能遗漏”。新 Agent L4 撤下原完整需求参照依赖及 PCmpS 完整度分数；PCS/PRC 仍是辅助 Agent 评分，不能叫从业者实验。历史真实人工研究单独核验和报告，不因本协议自动删除或冒充新评价。
