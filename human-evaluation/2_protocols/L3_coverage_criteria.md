# L3 需求覆盖：参照构建与覆盖判据

L3 评价生成用例对目标相关需求的覆盖程度。

## 参照项粒度

参照项仅保留"用例应表达的行为性要求"，即包含**主体、动作、对象、条件、结果**的行为描述；**界面布局、表单字段、协议参数等实现细节不纳入**。这样参照清单与用例的行为语义对齐，避免用实现细节惩罚合理的设计选择。

## 覆盖标签

| 标签 | 含义 |
|---|---|
| FULL（完整覆盖） | 需求项的行为语义在输出中被完整表达 |
| PARTIAL（部分覆盖） | 需求项的核心动作被表达，但条件/对象/结果有缺失 |
| NOT_COVERED（未覆盖） | 需求项在输出中没有任何对应表达 |
| CONTRADICTED（矛盾） | 输出与需求项的要求相反（做了不该做的、或状态相反） |
| UNRESOLVED（来源未决） | 源文档本身歧义，无法判定应否覆盖；单列展示、不计入分母 |

## 分母与汇总

- 分母 = **1367 个已确认参照需求项**（FULL + PARTIAL + NOT_COVERED + CONTRADICTED）。
- **636 个来源未决项**单独记录、不计入分母。
- **宏平均**：按文档等权，先算每个目标的完整覆盖率，再对 6 份文档取平均。
- **微平均**：Σ FULL / 1367（全部已确认参照需求项）。

## 评阅组织

由三名专家承担：专家甲构建参照、专家乙独立复核覆盖判定、专家丙裁决分歧，最终采用 RECONCILED 标签。参照构建与覆盖判定均不接触生成结果（先建参照、后评产物）。

## 关键结果

- AUCMR：完整覆盖 473、部分 284、未覆盖 597、矛盾 13，文档等权宏平均 **47.80%**、微平均 34.60%。
- ReAct-Elaborate：宏平均 45.05%。
