# PURE L5 Agent 评价 v3：按来源行定位与兼容续跑

版本：`AUCMR_L5_PURE_AGENT_3.0.0`。本目录是 v2 停止后建立的执行兼容版本；父级 v1 及 `revision_v2/` 保留原文件、冻结清单、响应和失败记录。本文件不表示正式任务已启动或评分已完成，实际冻结与运行时间以机器记录为准。

## 1. 修订原因与时间顺序

v2 完成 24/29 个目标的最终来源参照；129 个角色任务通过，5 个角色任务在固定技术恢复次数后失败。164 次接口响应均为 HTTP 200，35 次尝试未通过校验。全部 29 个参照尚未形成全局冻结，产物正式评分为 0/58。

剩余失败涉及 PDF 表格多列文字交错、跨来源段落或页面的引用，以及将语义概括填入逐字 quote。v2 的排版归一化不应把一般改写或被跳过的业务文字判为原文，因此本版增加确定性的来源行定位接口，而非模糊语义匹配。用户于 2026-11-02 要求修改兼容并给出继续执行指令；本版修订发生在 v2 参照尝试之后、v3 继续执行与任何正式产物评分之前。不得称为生成前全部预注册。

## 2. 共同来源行目录

宿主程序从既定共同需求的每个 source part 原文，按固定的 `splitlines(keepends=True)` 方式建立 1-based 行目录。目录只包含已经允许提供的 source part ID、页码、行号及原始行内容，不访问隐藏用例正文、完整 PDF、生成记录、私有映射或外部资料。所有来源型角色都获得同一确定性目录；行目录是同一文本的定位视图，不引入新业务事实。

证据仍可使用 v2 已登记的 quote 定位；也可返回：

```json
{"part_id":"SRC-003","line_start":4,"line_end":6}
```

执行器验证 part 和行号范围，直接从原始来源提取对应字符区间，保存精确原文、起止位置、页码及 `source_line_range` 定位模式。多个 source part 或页面应使用多条证据，不合成一条声称连续出现的引文。表格交错文字仍保留在提取的原文区间中，不能自动删去否定、数量、相邻列文字或其他业务限定。

若模型同时提交非逐字说明或 caption，该文字另存为模型报告内容；只能将程序从原文提取的字符串标为 exact quote，不能把模型说明冒充已验证引文。行号定位仅证明引用位置存在，不能自动把行为断言判为 S、确认参照义务，或证明被引文本支持模型解释。支持性、范围、原子化及表格关系仍需来源复核与裁决。

不存在的 part、越界、负数、非整数或歧义位置继续作为机械错误恢复处理。原始共同材料和 A/B 本身不改写；本版不增加编辑距离、关键词相似、一般改写或其他模糊匹配。

## 3. 继承已通过的 v2 记录

本版采用兼容续跑，不因分数或预期胜负选择重新评价。v2 尚无正式产物分数；拟继承的对象仅为已经通过的来源阶段角色记录。每条继承记录必须同时满足：

1. v2 的 job 为 COMPLETED，记录哈希、原始请求、模型身份和父冻结证明可追溯。
2. 当前角色、目标、供应商、模型及实质任务数据与父请求一致。比较使用去除执行元数据后的规范化 JSON；新增的纯派生 `citation_catalog` 不作为业务输入变化。不能以“差不多相同”代替哈希一致。
3. 记录通过 v3 兼容验证；其来源义务、标签、理由和原始模型身份不得被静默改写。
4. 明确保存来源版本、父记录路径及哈希、原始请求哈希、新验证结果与继承时间。不伪造一次 v3 模型调用，不把父请求说成采用了 v3 新提示。

新版本的继承清单应逐条公布实际接受和拒绝的记录。129 条是 v2 可供检查的通过记录上限，最终实际继承数量以验证清单为准。24 份已完成的最终参照只有在依赖的构建、独立复核、盲读及裁决输入均一致、记录全部通过检查时才可继承。

已通过的 v2 记录本身仍原样保留；v3 中的使用由显式继承证明连接。新增行目录不被倒推成旧模型曾经看到的材料。不将继承记录计为本版新 HTTP 请求，也不增加独立模型、评审者或项目样本数。

## 4. 未完成角色及新调用

对 v2 固定失败的 5 个角色任务，以及它们阻塞而尚未执行的下游角色，使用本版固定队列继续。失败请求不当作有效首判、空产物或零分。兼容版本为需要恢复的角色登记新的固定技术尝试预算：最多 4 次，包含首次与 3 次恢复；父版已经使用的尝试保留并单列，不删除或伪装为没有发生。

若父失败角色的数据和身份一致，可向该角色提供其自身最后一次失败响应及具体错误，再附本版来源行目录，要求修复引用或结构问题。该恢复不得给独立角色其他角色未授权的材料，也不得使其看到候选产物、方法标签或评分。重试不能依据 A/B 得分，不选择更有利的有效判断，不无限增加次数。

模型绑定和参数沿用 v2：Qwen / DeepSeek 两个家族、Junxi 凭据、温度 0、输出预算 32768 tokens、超时 300 秒，具体值以冻结配置为准。原始与实际返回模型逐次保存；不回退其他账户，不打印密钥。若参数、服务或执行能力不可用，应保留失败状态，不以合成响应替代正式判断。

## 5. 全局参照门控与公平评价

所有 29 个目标的来源参照及其构建、独立复核、先盲读后裁决过程必须完整，继承与新记录一并检查并冻结后，才可开始正式产物评分。缺少真实候选去向、复核或必需审计意见，仍须技术恢复；不能自动改为来源歧义以缩小分母或跳过门控。

v2 未进行任何正式产物评分。因此双方全部 58 份产物的两个独立首判、去标签对齐、裁决和固定稳定性复评，都在 v3 统一进行，双方获得同样共同需求、来源行目录、冻结参照及规则。来源阶段已完成记录的技术继承不能被描述为复用更有利的 A/B 评分。

C/K/R 的原子化、范围、空项、Q、未决、零分母和聚合规则不变：C 为明确适用义务的 1/0.5/0 均值；K 为去重断言 `S/(S+X+U)`，来源 Q 单报；R 为不必要重复数/全部行为单元数。真实评审不确定仍记录 null 和影响，不强迫多数票判真。来源参照未决按 L5 规则单列，不采用 L3 固定分母公式。名称与主要参与者不计识别成绩，无任意综合分。

队列、项目分层抽样与种子沿用 v2；项目内目标等权、项目间等权，项目聚类 bootstrap 10000 次、seed=20261101。独立首判均值与裁决结果分别报告。断言数、调用次数、继承记录和多个 Agent 不能充当独立项目样本。

## 6. 验证、交付及运行边界

本版正式执行前须验证：来源行目录和原文字符映射、跨 part 证据分列、表格交错内容保留、非法行号拒绝、模型 caption 与 exact quote 分离、继承数据/身份/哈希一致、错误继承拒绝、父记录不可变、请求和统计中继承与新调用分开计数、失败恢复及全局参照门控。

测试使用独立合成样例，不能将其当正式来源参照或评分。旧响应回放只作回归验证，也不产生新的正式模型判断。实际测试状态和继承数量以验证文件为准；不预先填写通过或人工确认。

用户要求提供继续执行指令，本次准备不自行启动正式长任务。冻结完成后，用户可在本目录运行 `python -B start.py`，通过 `python -B progress.py` 查询进度。程序完成后生成结果文件；未完成前不报告质量胜负。

最终结论仍限定为：在选定 PURE 材料及共同证据范围内，Agent 对 AUCMR 生成稿与既有人工文本用例的质量评价。U 仅表示共同需求无法证实；Agent 一致性不能证明准确性、真人验证或专家水平，也不能以差异不显著证明相当或严格不劣。
