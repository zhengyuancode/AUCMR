# PURE L5 Agent 评价 v2：执行与证据定位修订

版本：`AUCMR_L5_PURE_AGENT_2.0.0`。本修订适用于 `agent_evaluation_v1/revision_v2/` 中的新执行批次。具体冻结时间、脚本与提示哈希、参数和实际模型标识以本目录机器记录为准；本文存在不表示正式评价已经完成。

## 修订依据与时间顺序

用户于 2026-11-02 明确要求修复失败原因并重跑，允许在模拟人工评分时适度放宽规则。v1 已结束于 `BLOCKED_REFERENCE_TECHNICAL_FAILURE`：124 次响应均为 HTTP 200，101 次响应未通过校验，23 次角色任务通过；29 个目标仅形成 1 份最终参照，未形成全局参照冻结，正式产物评分为 0。因此本修订发生在 v1 参照尝试之后、v2 参照与全部正式评分之前。完整失效原因和证据定位见 `diagnosis.json` / `DIAGNOSIS.md`，不得将本修订称为生成前预注册。

已观察到的实现问题包括：PDF 文本换行、空白或 Unicode 排印差异导致可定位引文被拒；模型把行政字段留空或以单字符串返回，导致 schema 失败；`read_parts` 只列相关段落时被误当未阅读；复核同时给出构建者候选与独立首稿意见时，合法额外候选被拒；明确排除且 `final_ids=[]` 的裁决没有被识别为排除记录；技术恢复仅给错误消息，没有提供需修复的原响应，导致重新生成时引入其他格式错误。

“人类也会出错”在这里意味着记录、容纳和复核错误，不意味着把无法定位的证据或遗漏的判断自动授予正确分数。

## 保持不变的实验条件

1. 材料仍是既定 29 个目标、58 份匿名产物和相同共同需求。原有输入、A、B、生成提示、配置及日志、人工协议与评审包只读保留。
2. 不重新生成或修改 A/B，不选择替换目标，不按预期质量筛选。v1 全部记录保留；v2 统一重建全部 29 份来源参照，并对双方全部 58 份产物重新进行两模型首判、盲态对齐、第三角色裁决及预定稳定性复评。v1 成功首判不作为 v2 的正式判断复用。
3. C 仍为 CONFIRMED 适用义务的 1/0.5/0 覆盖均值；K 仍为去重断言的 `S/(S+X+U)`，来源歧义 Q 排除并单报；R 仍为不必要重复数／全部行为语义单元数。名称与主要参与者不计识别成绩；不存在任意综合分。
4. 来源参照只能依据共同需求，不读产物、隐藏用例正文、完整 PDF、生成记录或私有映射。评分角色仍只看一份匿名产物、共同需求、全局冻结参照和统一规则。API 无文件、命令、浏览或其他工具。
5. 两类模型、角色关系、Junxi 凭据授权范围及匿名编码保持相同；请求与实际返回模型分别记录。Qwen 裁决者与 Qwen 首判同家族，DeepSeek 首判与生成模型同源，不能声称三个独立模型家族。
6. 呈现队列、项目分层抽样和种子保持不变。项目内目标等权、项目间等权；项目聚类 bootstrap 10000 次、seed=20261101。技术失败不计零分，未决不强迫多数票判真。

## 可接受的格式容错与原文映射

所有格式适配都保存模型原始响应、适配后的记录及逐项适配原因，不覆盖原响应。机械定位只证明位置，不证明语义支持。

- 优先使用区分大小写的逐字匹配；仅在不能逐字匹配时使用预先固定的 Unicode NFKC、空白折叠及明确登记的排印归一化。软连字符、行末断词连字符或弯引号等只有在定位器已登记且验证过相应规则时才接受。不能把一般词汇替换、数值变化、否定删除或语义近似包装成格式容错。
- 归一化匹配必须能够回映到原始文本的字符区间，并同时保存模型请求引文、精确原文、匹配模式、页码和 part。原始共同来源及产物本身不被改写。
- 若模型给错 occurrence，但该精确或受限归一化引文在允许范围内只有唯一位置，可纠正该位置索引并留痕；存在多个候选位置且无法确定时不得猜选。
- 若引文在所声明 part 未匹配，但在本次明确提供的其他 part 中有唯一可定位位置，可修正 part/page 并保留原定位。不能扩展到隐藏正文、完整文档或外部材料；多位置或根本找不到时继续技术修复或保留未决。
- 引文只做格式归一化后仍不在共同源中，不能因此把其断言标 S，也不能自动断言为现实世界虚假。

## 行政字段与真实判断分开处理

- 缺失/null 的纯行政空列表（例如没有历史来源可填的初稿 lineage，或未报告问题的行政容器）可按已登记规则转换为 `[]`；非空的单个 lineage 字符串可转为单元素列表。每次转换留痕。缺失的覆盖值、支持性标签或裁决意见不按此规则补成确定判断。
- `read_parts` 保留模型实际自报；执行器另外记录完整 `supplied_parts` 和请求哈希。不得将“已提供”冒充“已阅读”，也不因模型仅列相关 part 就拒绝整份记录。未知 part 或证据位置仍必须明确处理。
- 复核必须覆盖每个构建者候选；也允许给出已知独立首稿候选的额外意见。没有填写的候选意见继续进入预定技术修复，不能自动改为 CONFIRM、UNRESOLVED 或“已复核”。恢复次数耗尽后，保留失败并阻止不完整参照通过门控。未知 ID 不被静默映射到一个看似相近的候选。
- 最终参照中，候选可映射到确认、合并、拆分、未决义务，或有明确来源依据和理由的排除裁决。`decision=exclude` 且 `final_ids=[]` 是合法的明确排除记录，保留 tombstone，不强造一个分母义务。
- 对既无最终去向、也无明确排除依据的上游候选，不静默删除，也不自动生成为 UNRESOLVED。固定技术恢复要求裁决补充；仍缺失时，最终参照不完整，保留失败并由全局门控阻止评分。遗漏的评价意见不同于来源自身歧义，不能通过缩小 C 分母掩盖执行缺口。
- 只有 Agent 明确给出理由的来源或范围语义未决，才按 L5 原规则不进入 C 分母并公布原因和影响。执行器不将行政遗漏转换为此状态，不能用较小分母宣传参照完备。
- 评分允许明确的真实评审不确定性以 `null` 和受影响指标记录保留，随后提交裁决；不能仅因为角色不确定就把整个接口响应当零分。C 的适用义务分母不因此删除，K 的评审不确定不冒充来源 Q；受影响点估计与界限沿用现有未决规则。
- 若裁决缺少某项必需审计说明，继续预定技术修复；耗尽次数后保留为失败，不伪造“已检查”或“保留原判”的意见，也不把最终分值存在当作审计完成。最终交付必须公布复核与审计完成度。

## 固定恢复与运行参数

v2 每个逻辑请求最多 4 次尝试，含首次与 3 次固定技术恢复。恢复请求提供同一任务、已保存的前次原响应以及具体机械错误，要求只修复技术结构/定位问题；不得因某方得分、方法身份、偏好或预期胜负重跑。所有尝试及原响应均保留。成功且请求哈希相同的 v2 记录只复用，不选择更有利的新结果。

输出预算调整为 `max_tokens=32768`，温度 0，超时 300 秒；其他实际值以评分前冻结的 `config.json` 为准。预算增加仅处理既有截断风险，不改变候选原文、原子化要求或评价公式。模型服务若不支持参数必须如实报告并登记，不静默改变模型或账户。不得截断义务以强行使格式通过。

全部 29 份参照完整通过校验，并连同全部语义未决与排除记录冻结后，才可评分。未修复的复核或候选去向缺口不能仅凭留有记录跨过门控。源参照为 Agent 参照，不是官方 gold 或人工金标。v2 的原始与适配记录、固定队列、调用、引用映射、未决、技术失败、审计完成度及统计输出都须独立保存。

## 验证与解释限制

正式执行前使用合成样例验证格式容错、严格拒绝语义改写、原文字符映射、错误 part 的唯一迁移、行政列表容错、遗漏候选留痕、未决处理、匿名访问边界、固定队列和失败恢复。不得用模拟响应充当正式评分。

本修订不保证评审准确。容错与评审错误会分别统计；来源支持、范围归属和原子化仍依赖 Agent 判断。最终结论仍限定为：在选定 PURE 材料及共同证据范围内，Agent 对 AUCMR 生成稿与既有人工文本用例的质量评价。不能据差异不显著证明相当或不劣，不能据 Agent 一致性宣称专家验证或真人评分。
