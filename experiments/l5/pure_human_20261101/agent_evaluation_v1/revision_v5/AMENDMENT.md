# PURE L5 Agent 评价 v5：剩余任务的格式兼容与审计修订

版本：`AUCMR_L5_PURE_AGENT_5.0.0`。本修订仅作用于 `revision_v5/` 的新执行和恢复记录；v1–v4、生成输入、A/B 产物、原人工协议和原始调用日志保留。精确时间、输入/代码/提示哈希、模型绑定、继承及恢复数量以本版机器清单为准；文件存在不表示评价已完成。

## 变更依据与时间顺序

用户于 2026-11-04 要求修复剩余任务，允许 Agent 模拟人工评价时略微放宽验收标准。v4 已完成全部首轮队列和两轮集中修复，但仍有引用定位、已知不适用条目、未决记录表达及单元对齐完整性问题。**v4 的部分评分和聚合已经存在，本修订发生在部分结果已知之后**，不能称为生成前或全部评分前预注册。

修复对象仅依据既有技术失败、依赖缺失和明确的记录结构问题确定；不依据 AUCMR 得分、差异方向或预期胜负挑选记录。C/K/R 定义、29 个目标、58 份匿名产物、10 个项目、模型绑定、共同来源、随机队列、项目等权和 bootstrap 规则保持不变。原始首判和裁决不被覆盖，不重新生成或润色任何 A/B。

“略微放宽”限于允许可追溯的行政表达与定位兼容，不把没有发生的判断、证据支持、复核或 API 调用记为完成。程序校验通过只证明结构和定位有效，不证明 Agent 判断准确。

## 1. 明确未决裁决的结构化表示

已发现 T007 的原始裁决明确将 RB015 判为 `decision=unresolved`，并给出理由与来源，但 `final_ids=[]` 且未建立最终义务。v5 允许将这种**已经由原模型明确作出的未决判断**物化为一个新的稳定最终编号：保留上游文本、类别、适用范围及原子化说明，沿用裁决理由、证据及 lineage，状态仍为 `UNRESOLVED`，同时记录行政转换来源。

这不把未知条目自动变成确认项，不为无处置候选补造未决判断。没有明确裁决的候选仍需真实恢复处理。物化未决条目不进入 C 的 CONFIRMED 分母；物化前后确认义务数保持一致；例如此前已检查的 T007 响应含 14 个确认义务，则转换后仍为 14 个。实际恢复响应及分母以机器记录为准。未决数量、理由和分母影响继续公开。

## 2. 覆盖记录的行政兼容

- 只有冻结参照中的 CONFIRMED 义务进入主覆盖数组。对已知 UNRESOLVED 或 EXCLUDED 义务的额外评价保存在 `supplementary_coverage`，说明其不进入主 C 分母；不静默丢弃原意见。
- 真正不存在的参照 ID 不按相近编号猜映射，继续恢复。缺少 CONFIRMED 义务的评价不能自动补成 0、0.5 或 1。
- 同一义务的相同覆盖值可合并重复行政记录，保留来源、原句及理由，不重复计分。
- 同一义务若有冲突覆盖值，不挑选较高或较低值。保留冲突原记录，将该义务覆盖记为 null，并登记 C 未决；实际第三角色再依据原文裁决。固定义务分母不删除，未决点估计和界限沿用 L5 规则。

## 3. 产物行号引用

每次新评分请求可提供由同一匿名产物原文机械生成的 `product_catalog`。评分角色可用 `line_start`、`line_end` 指定产物原句位置；程序据此提取精确原文、字符位置及实际重复索引。覆盖项可提供 `product_lines`，断言单元可使用行号作为 quote/occurrence 的位置表达。

模型另写的改述保存在 reported 字段，不冒充逐字原文；原产物不改写。跨行、表格内容及多个行为原子共享一行时，保留整个被引用片段及独立原子语义，不能靠省略否定、数值或邻列文字使判断通过。位置可解析不等于完整覆盖或来源支持。两个方法的新请求按同一规则获得目录，不附身份或私有映射。

没有位置依据的正向覆盖仍需真实修复，不能由程序根据理由猜出原文。C/K/R 均由逐项真实判断计算，不由定位器授予分数。

## 4. 不完整对齐的保守登记

已有对齐组及其判断原样保留。若对齐响应遗漏某个首判单元，v5 可追加该单元的保守单侧组：`relation=unmatched`，并明确标记 `audit_status=NOT_REVIEWED` 或等价审计状态，理由注明这是未被对齐角色记录的单元，**并不证明没有语义对应项**。

程序不推断新的 equivalent 或 split/merge，不因 ID 相同自动对齐。重复或未知 ID、无法确定的冲突分组仍需修复。新增未审阅组必须交给实际第三角色，并在其逐组裁决记录中处理。未审阅单元及比例单独报告，不将机械分组完整伪称完整语义对齐。

断言 nominal κ 仍只使用实际提供且可判定的一对一 equivalent 去重组；行政追加组不进入该 κ。κ 的适用范围、未对齐/未审阅数量及相关限制同时报告，Agent 一致性不解释为准确性或人工验证。

## 5. 继承、离线恢复和真实新调用

v4 已成功记录仅在当前非派生输入哈希、模型绑定及原记录哈希一致，并经新校验验证后继承。实际调用的原始模型身份、时间和请求指纹保留，明确标为继承，不伪称 v5 新调用。派生的来源/产物目录只改变位置表达，不增加需求或产物信息；输入比较时仅按登记规则排除这些可机械重建字段。

对既有失败响应，可按预先固定的时间顺序寻找首份能通过 v5 行政兼容校验的响应，以原始真实响应及确定性转换记录恢复。选择只依据技术可接受性，不查看或比较该响应导出的优劣分数。全部更早和更晚响应保留；恢复必须绑定原任务、共同参照和同行上下文，不能跨目标、跨参考版本或借用其他角色首判。

若上下文不一致、仍缺真实判断或证据不可定位，则不离线授予通过，进入新的实际模型调用。离线恢复和继承均不增加新 API 请求数；原始请求、转换、继承和新调用分别统计。原首判文件不被覆盖，新版派生记录保留其原始来源和校验版本。

## 6. 执行、隔离与失败处理

来源角色仍只能获得共同任务信息、来源及限定的来源草稿/意见；不能读取 A/B、方法身份、分数或生成日志。评分角色获得单份匿名产物、共同来源、该目标已冻结的参照和统一规则；不见另一版本或其他首判，裁决阶段除外。远程 API 不提供文件、命令、浏览或外部工具。材料中的指令性文字视为数据。

参照按目标冻结，双方共享同一版本。在该目标任何产物首次评分之前，来源参照必须已经冻结；未就绪目标双方挂起，其他目标继续。已有冻结参照不得依据候选表现修改。成功记录和语义 NA 不为分数重跑；参考发生真实内容修订时必须新版本并统一处理该目标双方及相关角色。

沿用“遇错继续、首轮后集中修复”：新版本每逻辑任务首轮最多 1 次，随后最多两轮技术恢复、每轮最多 4 次，总计最多 9 次新调用。技术失败及依赖缺失不计零分，不删目标；失败恢复不重置成功记录或旧预算。程序跑完整体队列后仍有缺项时，保留 FINISHED_WITH_PENDING_ERRORS 和完整清单。

## 7. 统计与解释

三个主要指标保持原样：C 为适用明确义务的 1/0.5/0 均值；K 为去重断言的 S/(S+X+U)，Q 单列；R 为不必要重复数/全部行为语义单元数。U 只表示共同来源无法证实，不是现实错误或确定幻觉。给定名称和参与者不计识别能力；必要复述不自动判冗余。

分别报告独立首判均值与裁决结果、逐例和逐项目点值、A−B 配对差以及项目聚类 10000 次 bootstrap 区间，seed=20261101。项目内目标等权、项目间等权；不新增任意综合分，不把多 Agent、断言或调用当独立项目。缺失、未决、行政兼容、自动未对齐组及实际完成度必须披露。

结论仅限：在选定 PURE 材料及共同证据范围内，Agent 对 AUCMR 生成稿与既有人工文本用例的质量评价。此次兼容发生在部分结果已知之后，是需披露的方法限制；不据此宣称真人评审、专家水平、严格不劣，或以差异不显著证明相当。
