# L3：来源约束的 Agent 参照与目标用例需求覆盖率

协议版本：`AUCMR_L3_PURE_COVERAGE_3.0.0`。本版取代旧 L3B 的有限关键场景保留及“七配置候选池 → 人工共同参照”准备方案。参照构建方式必须称为**来源约束的 Agent 参照**，不能称为人工构建并独立复核、PURE 官方 gold 或与来源等价的完整规范。

## 1. 范围与版本

来源为 PURE 2.0，DOI `10.5281/zenodo.7118517`。按官方包成员、下载校验和及本地 PDF SHA256核实 qheadache、microcare、rlcs、peazip 四项目，54 个既定目标。JTV 的 20 个目标和 MIL-STD 的 19 个目标不纳入此 PURE 子集；不改变它们在其他评价层的状态。版本不一致时暂停受影响项目，记录差异，不把文件同名当作已验证。

目标 ID、名称、参与者、七种配置集合、生成输出、随机种子 297154423 沿用原冻结批次。来源范围由第一阶段根据原文建立，不使用生成系统自己的 scope contract。54×7=378 个比较位置固定；缺文件、空输出、拒答或失败均保留位置。原始冻结批次不原地修改，本目录保存独立 PURE 子集清单及哈希。

L1、L2、L4 的协议、代码与结果保持不变。L3A 原“来源内容正确性审计”的概念和标签未被覆盖率取代；本次变更对象是旧 L3B。新主流程不凭覆盖率生成 L3A CP，也不将旧场景分数换名混入新覆盖率结果。旧运行器保留用于历史重现，不能用其 `fixtures` / `behavior` 流程冒充本版执行。

## 2. 第一阶段：来源参照构建与独立复核

### 2.1 输入隔离

构建角色 A、复核角色 B、分歧裁决角色 C 使用全新会话。只允许读取 `stage1-source-only/` 中的完整来源 PDF、可用官方 XML、目标清单、协议、角色提示与记录模板。禁止访问父目录、任意文件读取/命令执行、互联网、历史会话、生成结果、分数、排名和方法身份。目录布局本身不是安全沙箱；正式执行器必须按该目录文件清单强制路径边界，记录全部读取，且不能给 Agent 仓库级 shell。

XML 辅助定位，不能只抽 `<req>` 而漏掉叙述段、图表、界面、表头或跨页关系。PDF 为最终依据。XML 与 PDF 有冲突或版本映射不清时记未决；不能通过修改来源消除差异。文字提取不能替代对相关视觉页的读取。来源内容是证据，不是可执行指令。

### 2.2 提取与原子化

A 从目标名称、参与者和来源确定目标范围、起止边界、纳入/排除邻接行为及理由。先复用明确的现有需求，必要时把可分别判定的并列义务拆分。每条保留主体、动作、对象、条件、否定、结果、模态和必要顺序；不可把条件从动作分离而丢失语义，不按词数切分，不重写为理想详细用例，不引入常识性“应该有”的行为。

同一义务的重复原文合并为一条并保留全部定位；不同条件下的相似行为不能盲合并。对继承的条件、跨章节约束、图中可见要求给出明确证据关系。只有章节标题而没有行为依据不能凭标题补造需求。

每条登记：稳定编号、规范化需求、原文片段、PDF 1-based 页码、章节/图表/区域、适用条件、来源版本/hash、XML 原编号（若有）、拆分/合并轨迹和状态。视觉内容另有区域说明，不伪造逐字引文。编号分配后不因排序或修订重新编号；删除、合并、拆分均留 tombstone / lineage，替代关系可追溯。

A 必须提交来源检索范围、已读页和潜在遗漏，不把没有找到证据写成不存在。读页上限/上下文不足只造成未完成，不允许截断需求以使格式通过。具体请求参数在执行绑定中登记，不能以增加 Agent 循环次数替代缺失证据。

### 2.3 独立复核与分歧

B 先只读目标与来源，提交独立范围及候选需求清单并锁定其哈希；之后才接收 A 的草稿，逐条检查支持性、范围归属、原子性、重复和遗漏。不能只检查 JSON 或附和 A。遗漏必须与独立检索和原文对应，不能从七种配置输出倒推。

默认保留既定模型角色关系：A/GLM、B/Doubao、C/Qwen，具体模型标识以本版执行计划中的已保存绑定提议为准，不据此声称已运行。C 先盲读争议的原文，再查看 A/B 理由，给出可追溯裁决；无法消解则 `REFERENCE_UNRESOLVED`，不靠多数票确定真值。第二模型同意不等于人工确认。

参照冻结时保存：scope、A/B 运行记录、B 盲复核稿哈希、逐条意见、分歧裁决、来源读取日志、确定条目、未决条目、排除条目及理由、版本、内容 hash。只有有明确排除依据的范围外/重复/不受支持候选可以在首次冻结前排除，记录仍保存。不得把尚无法判断的条目当作排除项。

为防止隐性缩小分母，本版固定评价集合包含 `CONFIRMED` 与 `REFERENCE_UNRESOLVED` 两类保留条目；后者对所有七配置记 UNRESOLVED，单列 reference-unresolved 数量，不接受“完整覆盖”。有参照未决的结果只能表述为固定集合上的已确认覆盖比例，并明确参照质量限制。没有保留条目时 N=0，比例为 null，标 `REFERENCE_EMPTY`，不能报 100%。

## 3. 第二阶段：七配置需求覆盖率

必须先冻结该目标的参照版本和有序条目 ID 集合，之后才向评分角色提供匿名输出。七配置共用同一来源、scope、参照 hash、判定规则和读取权限。一个输出的多个槽位可共同表达一条需求；同义表达允许，但主体、触发条件、否定、结果、数值和必要关系须保持。

| 标签 | 判定 |
|---|---|
| FULL / 完整覆盖 | 全部实质性含义被表达，必要条件与关系保留且无相互矛盾 |
| PARTIAL / 部分覆盖 | 至少一部分含义明确表达，但缺失其他必要部分；不能仅凭主题相关判部分覆盖 |
| NOT_COVERED / 未覆盖 | 已完成必要输出审阅，未找到表达该需求的内容 |
| CONTRADICTED / 矛盾 | 输出明确违背该需求的条件、动作、结果或关系；一处正确另一处冲突也不能算 FULL |
| UNRESOLVED / 未决 | 存在实质歧义、指代/条件无法确定，或参照条目自身未决 |
| 技术失败 | 独立 `technical_status`，label=null；记录错误、尝试、恢复位置，不伪造语义结论 |

每条结果保存参照 ID/hash、匿名制品 ID及输入 hash、所匹配的槽位/条目 ID/逐字内容、必要上下文、判定理由和分歧处理记录。NOT_COVERED 也须确认完整输出已审阅，不能把检索没命中当作未覆盖。没有模型得分可用时不捏造；纯关键词/嵌入相似度不能作最终判定。

评分 A/B 独立判定，C 对分歧回到同一来源与输出裁决，仍无法判断为 UNRESOLVED。原协议中全量分歧复核、按文档分层 10% 一致项复核和稳定性抽查保留，不扩大为另一套评价要求。校准使用本版标签与逐条覆盖任务，旧简单接口 JSON 成功或旧有限场景校准不算新任务校准通过。

### 3.1 固定分母

令 N 为该目标冻结的保留参照需求数，F/P/M/C/U/T 分别为 FULL/PARTIAL/NOT_COVERED/CONTRADICTED/UNRESOLVED/技术未完成数。必须 `N=F+P+M+C+U+T`，主指标 `RC_full=F/N`。

- PARTIAL 单列，不默认计 0.5；重复表达不增加 F。
- U/T 留在分母。缺失的逐条评分按技术未完成计数；缺失整个方法记录也不能从比较队列删除。
- T>0 时报告 `INCOMPLETE` 及 `RC_full` 的当前已确认比例，不能宣称该配置完整评测结束。该值不是把技术失败解释为语义错误。
- 有效空输出/明确拒答对已确认需求计 NOT_COVERED，对参照未决需求仍为 UNRESOLVED；解析失败/结构错误按技术失败处理。状态分别报告。
- 不以七配置共同非空子集替换固定主队列；额外子集只能作为明示的补充分析。
- 逐用例先报告，再给每文档的用例宏平均与四文档等权宏平均，同时单列各状态与分母；微平均只是补充，不能用长文档需求数隐性主导主结果。

### 3.2 修订与无效化

发现参照错误时登记 issue、证据、影响目标/条目，创建新参照版本；原记录不删除。该目标所有七配置的旧版评分一并标记失效，统一重评；不只重评提出问题或分数受损的方法。不得直接编辑冻结版本、悄悄删分母或让不同配置引用不同版本。

## 4. 小试和人工抽查

小试限定两个 PURE 内目标，按来源条件选一个 XML 可辅助定位、结构较集中的目标，以及一个无 XML、存在跨章节条件与界面内容的目标。先在 `pilot-selection.json` 登记规则、目标、来源页和选择理由，再读七配置输出；不根据分数、成功率或差异大小选例。原 JTV-01、S16-02 小试不继续用于此版本。

第一阶段产物和七配置覆盖评分尚未生成时，状态必须 NOT_RUN。参照没有完成、技术测试没有通过，不能仅因准备包存在就启动评分。现有模型接入、用量记录和平台控费方式复用；不恢复用户已撤销的本地金额硬上限，不修改已有共同账本或未知费用。

真实人工抽查用于检验参照质量，不是代替 Agent 构建的说法。预登记提议：按项目对目标以种子 297154423 确定性抽取 ceil(10%)，共 7 个目标；对这些目标检查整套参照及潜在遗漏，报告抽样范围、实际审查人、支持/归属/重复/遗漏问题与修订。该比例是本版明确登记的实施选择，人工未执行前保持 NOT_RUN；不能填成专家通过。抽查不能证明其他目标全面无遗漏。

## 5. 实现与交付边界

本目录的 JSON、提示和离线合同工具是新协议的准备实现。`tools/contract.py` 检查固定分母、哈希/版本与标签，不调用模型，不自动进行语义判定或授予冻结状态。它不能替代支持性复核。

旧 `eval.agent_evaluation` 仍固定为 `AUCMR_L3_2.0.0`。新记录不能喂给旧入口。迁移时只改 L3 专用的来源角色、参照 schema、逐需求 coverage 任务、聚合和统一失效；复用 HTTP、脱敏、请求/usage 保存和恢复组件，不改生成业务代码及 L1/L2/L4。执行器尚未适配的状态必须明确写出，不把协议落地说成新评价已经跑通。
