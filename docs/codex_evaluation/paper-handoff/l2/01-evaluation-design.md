# L2 评价设计与统计定义

## 目标、对象与边界

L2 评价一份生成完成的 Cockburn 风格 Detail-UC 内部的残余跨槽一致性问题。每个目标用例、每种生成方法构成一个评价项；不同方法的输出分别送评，不在同一个请求中并置比较。输入包括用例名、固定主参与者以及生成的槽位断言。方法名、方法排名、来源 PDF 和源文正确答案不作为规则裁判的输入。

七个内容槽位为 `goal`、`preconditions`、`trigger`、`main_flow`、`alternative_flow`、`exception_flow`、`postconditions`。`primary_actor` 作为固定背景提供，不构成第八个被评分槽位。L2 的结果是违规次数，不是七槽分数或平均正确性分数。

L2 不判断来源支持度、需求完整性或实用性。论文主实验统一采用原冻结输出，已完成的评价器修复保留。与 L1 的空槽指标、L3 的覆盖评价或 L4 的专家模拟评分联合讨论时，应先对齐目标 ID、方法及输入哈希。三份重生成输出仅为补充输入，不参与主表，也不与原输入的 L1、L4 分数直接配对。

## R1–R7 的最终定义

下表是当前执行定义的中文解释；完整英文规则逐字保存在 [data/protocol.json](data/protocol.json)，来源代码是 `eval/l2_judge.py` 中两组系统提示词。工程执行规则见 `eval/l2_rules_batch.py`。

| 规则 | 标识 | 判定含义 | 非空输入要求 |
|---|---|---|---|
| R1 | `trigger_preconditions_coverage` | 触发事件之前必须成立的独立状态应在前置条件中对应；构成触发本身的消息、点击、选择等事件无需重复写为前置条件 | preconditions、trigger |
| R2 | `mainflow_trigger_continuity` | 主流程第一步应与触发条件相容并承接它；为可读性简述发起动作不自动违规，实际断层、矛盾或另起场景才应报告 | trigger、main_flow |
| R3 | `mainflow_postconditions_reachability` | 主流程应合理导向每个后置条件；可达的界面、显示或结果状态允许作为后置条件，不强制持久化 | main_flow、postconditions |
| R4 | `actor_mainflow_presence` | 整个主流程中应出现主参与者，可通过名称、角色表述或代词表达；宾语、所有格和限定角色表述均可计入 | main_flow，并提供主参与者背景 |
| R5 | `goal_mainflow_alignment` | 目标应与主流程行为一致；执行定义不把目标中的长期、异步或系统持续行为作为本规则冲突依据 | goal、main_flow |
| R6 | `altflow_diverge_points` | 备选流引用的分支点应对应现有且相关的主流程步骤；分支特有条件不必已经写在主流程步骤中 | main_flow、alternative_flow |
| R7 | `exceptionflow_exit_coverage` | 每条非空异常分支应有明确结局：返回某步骤、终止、移交，或明确的拒绝、阻止、失败状态；不强制补造重试／返回动作 | exception_flow |

## 空槽与规则适用性

规则依赖的任一内容槽为空时，该规则记为 `NOT_APPLICABLE_EMPTY_INPUT`，不发送该规则供模型判定，不产生违规条目。不读取 `raw_text` 或生成时的中间草稿来补造缺失断言；绑定的是最终输出 `claims`。

R7 的异常槽为空时不适用。已有真实异常分支但没有结局仍可构成 R7 违规。生成器内部的 `coverage_state`、`missing_aspects` 等覆盖元数据不是异常分支。

R4 有一个充分条件检查：若主参与者名称以忽略大小写、单词边界匹配的方式出现在整个主流程任一断言中，程序记录原句与匹配位置，记为 `SATISFIED_LITERAL_ACTOR_PRESENCE`。不满足字面充分条件时仍交由模型按角色、代词等语义判定，不能据此直接判违规。R4 每份用例最多一个违规条目，不逐步骤重复计数。

含部分正文的用例可以完成 L2，其空槽对应规则仍为不适用。整份无可评价正文或生成明确中止的用例记 `NO_EVALUABLE_CONTENT`，违规总数为 `null`，不进入任何均值分母。

## 违规条目的单位与校验

每条违规包含规则、应修改的槽位、该槽位的断言索引和简短理由。断言索引从 0 开始；`-1` 只表示一个非空槽位的整体问题。流程中的 `step_number` 是文本中的步骤编号，不能与断言数组索引混淆。

最终校验要求规则属于当前分组，引用槽位与索引有效，理由非空。完全相同的结构化违规条目去重；理由不同的条目不会仅因规则或位置相同而自动合并。因此本指标统计的是**最终接受的违规条目数**，不是人工裁定的唯一缺陷数。除 R4 外，一个规则在一份用例中可对应多条违规。

JSON 格式、规则范围或位置不合法属于技术失败，不记成零违规。通过协议校验只证明格式、引用位置和执行约束满足要求，不证明模型的每项语义判断都正确。

## 汇总公式与分母

令 `v(i,m,r)` 为原冻结输入中目标 i、方法 m、规则 r 的最终接受违规条目数，`C` 为七种方法均完成评价的目标集合，论文主实验 `|C|=89`。

- 主表规则总次数：`T(m,r) = Σ[i∈C] v(i,m,r)`。
- 主表每用例规则均值：`M(m,r) = T(m,r) / 89`。
- 主表总违规：`T(m) = Σ[r=R1..R7] T(m,r)`；总均值为 `T(m)/89`。
- 完成覆盖率：`完成评价项数 / 计划评价项数`。AUCMR、消融配置、TextRAG 各为 `92/93`，VDocRAG 为 `91/93`，其余为 `93/93`；整体为 `646/651`。五项无可评价内容如实计为生成覆盖率缺失。
- 规则不适用用例数：在同一主集合 C 中，按最终 `rule_resolution` 统计每条规则的空输入情况。

部分用例的某条规则不适用时，其违规条目数在计数表中为 0，但“不适用”状态单独报告；主表仍采用统一分母 89，不改用每条规则的适用数量作为分母。整份无可评价内容的五项不补零，也不为补齐数量继续生成。该区分也意味着低违规均值必须结合不适用数量与生成覆盖解读。

均值展示保留两位小数，总计直接由整数总数除以 89，不能把四舍五入后的各规则均值相加作为总计。原输入全部可用样本的辅助表使用各方法自己的完成数量，不能替代共同集合主表。三份新输入对应的历史 649/91 表仅保留为补充实验视图。
