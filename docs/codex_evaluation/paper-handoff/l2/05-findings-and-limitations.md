# 结果解读、实例与有效性边界

## 能支持的结论

1. 原冻结输入对应646项协议完成的L2结果、0项技术失败、5项无可评价内容；七方法在89个共同有效目标上形成一致的主表分母。评价器修复保留，三份重生成仅为补充。
2. 不同方法的规则分布不同。备选流分支点R6是TextRAG、VDocRAG和ViDoRAG的重要问题来源；AUCMR仍存在触发承接与异常结局问题。
3. 空槽对计数有实质影响。未生成的内容不会产生对应规则违规，所以低违规数必须与适用性、空槽和覆盖信息联合解读。
4. AUCMR并非总计最优，也没有在总违规数上优于去掉跨槽检查的消融配置。本数据不能支持相反陈述。

## 不能由当前数据推出的结论

- 不能写“AUCMR在所有规则或总违规上最好”，也不能把较低违规数直接解释为更高的事实准确率或可用性。
- 不能写“专家一致认可”“26名从业者评价”或把模型调用次数当成独立专家人数。当前L2是单一模型服务的辅助判定。
- 不能写“温度0保证确定性”。实际请求未指定温度或种子。
- 不能写“所有93×7输出首次生成和评价均成功”；原冻结输入有五项生成覆盖缺失，三份后续重生成成功不改变主实验覆盖率。
- 不能声称显著优于、证明因果或证明无模型偏差。本交接没有运行显著性检验、人工精度标注或模型间一致性实验。

## 主要解释边界

**语义判定误差。** 严格JSON、规则ID和位置校验不能消除误报或漏报。例如，最终保存的个别R1理由仍可能把“收到消息”当作缺失前置条件，而规则文本明确不要求重复触发事件。此次交接保留原判断，不挑选性人工改分。论文应把结果称为模型判定的残余违规，不称为经人工验证的真实缺陷总数。

**规则适用性与产出密度。** 各方法留空比例不同；即使共同目标一致，各规则实际可检查内容数量仍不相同。主表回答的是“每个目标生成的内容中发现多少违规条目”，而非“每个可比较断言的错误概率”。

**条目粒度。** 除R4最多一个整流程判定外，其余规则可返回多条。完全相同条目去重不等于将所有语义重复缺陷人工合并；不同措辞理由可能保留为不同条目。

**最终记录来源。** 主实验使用原冻结输入对应的已保存评价，并保留完成的评价器修复，精确版本在数据里保留。不同记录并非全部来自同一次同版提示的重跑，论文不能宣称严格同批同版采样，也不能用当前HEAD冒充全部结果的生成版本。

**输入补充与共同集合筛选。** 原输入的五项无内容涉及四个目标，因此主比较为89个共同有效用例；五项全部计入生成覆盖率缺失。三份新正文及其L2评价单列补充，原649/91表不进入主实验。共同有效集合仍是一种条件筛选，必须同时报告93×7的覆盖情况。

**来源事实与跨层连接。** L2不读PDF，所以有引用不代表获得了来源支持；没有违规也不代表覆盖完整。L1、L4保持原输入和当前结果，L2主输入与之按目标、方法和输入哈希对齐；三份重生成的补充L2值不得与原输入的L1、L4分数直接配对。其他跨层分析同样需要核对输入哈希。

## 建议的论文表述范围

可以写“统一以原冻结输出作为主实验输入，采用GLM-4.6V独立执行R1–R7结构化规则判定并保留已完成的评价器修复；在七方法共同89个有效用例上统计每用例违规条目数，另报五项生成覆盖缺失和规则不适用数量。三份后续重生成及其评价仅作补充，不参与主表”。模型设置、选样范围及不利结果都应据此如实说明。
